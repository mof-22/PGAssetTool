# PGAssetTool

English version: [README.md](README.md)

ドット絵調シューター（Unity 2021.3 / IL2CPP）の AssetBundle を扱う Windows 向けツールです。
アイテムとそれが参照するすべてを一覧し、実際に編集できる形式でアセットを書き出し、編集を `.pgmod`
にまとめ、取り消せるバックアップ付きでゲームへ導入します。

ゲームのデータは一切同梱しません。パックは変更内容を記述するだけで、参照するのは利用者自身の
インストール環境にあるアセットです。

## 背景

アイテムのデータは数百のバンドルに分散しています。1つの武器のモデル・マテリアル・アイコン・
スキン・エフェクト・表示名はそれぞれ別の場所にあり、しかもそれらは単一の仕組みではなく
3種類の異なる方法で結び付いています。

| 参照の種類 | 例 |
| --- | --- |
| `PPtr` によるバイナリ参照 | `Material` → `Texture2D` |
| 実行時に解決される文字列パス | `"Weapons/Weapon25"` を保持するフィールド |
| 命名規則 | `Weapon687` ⇔ `Ray687` |

`PPtr` だけを追うとツリーは途中で切れます。本ツールは3種類すべてを追跡します。

## できること

- **一覧** — 全武器と、その下にぶら下がるアセット。名前はゲーム自身のローカライズバンドルから読みます。
- **プレビュー** — テクスチャを見る、音を鳴らす、モデルを回す。変更を決める前に確認できます。
- **書き出し** — 画像は PNG、音声は WAV、メッシュは glTF、それ以外はフィールドを読める JSON ダンプで。
- **差し替え** — テクスチャ・メッシュ・音声は普通のファイルから。それ以外のクラスもシリアライズされたバイトから。
- **新規追加** — バンドルに無かったアセットを追加し、既存のアセットをそこへ向け直す。
- **パック化** — 結果を `.pgmod` に。署名も付けられます。
- **導入** — 複数のパックを一度に導入、有効/無効の切り替え、削除。どのバンドルも最初の書き込み前に取ったバックアップから戻せます。
- **取り込み** — 他のアセットエディタで作った MOD を、このツールでパックできるワークスペースに変換。

## 必要なもの

- Windows x64
- ビルドには .NET 10 SDK。publish 済みのビルドは何もインストール不要です。

Unity のエンジン標準クラスの型定義である `classdata.tpk` はコアアセンブリに埋め込んでいます。
`*_Data` 配下のファイルは TypeTree を持たずにビルドされているため必要になります（AssetBundle は
自前で持っているので不要です）。Unity 標準クラスの定義のみで、ゲーム独自のコードとは無関係です。
[THIRD-PARTY-NOTICES.md](THIRD-PARTY-NOTICES.md) を参照してください。

## ビルド

```
dotnet build -c Release
```

GUI は自己完結の単一実行ファイルとして publish できます。

```
dotnet publish src/PGAssetTool.Gui -c Release -o dist
```

`dist/PGAssetTool.exe` は .NET の入っていない環境でも動き、書き出すものはすべて自分の隣に置きます。

## GUI

`PGAssetTool.exe` は3つのワークスペースで開きます。`Ctrl+1` / `Ctrl+2` / `Ctrl+3` で切り替えます。

**Browse** — 武器の一覧と、選択した武器が参照するすべてのツリー（モデル、マテリアル、テクスチャ、
音声、スキン、エフェクト）。テクスチャは表示され、クリップはスペースキーで再生、モデルはドラッグで
回転・`Shift` で傾き・中ボタンで移動・`R` で正面に戻ります。`Ctrl+Shift+R` でツリーを差し替え可能な
ものだけに絞り、`Ctrl+Shift+A` で透明度の書き出し方を切り替えます。`Ctrl+E` で選択中の武器を抽出。

**Editor** — 抽出済みのワークスペース一覧。抽出後に編集されたファイルに印が付き、そこからパックを
作って適用します。パックの名前・作者・バージョン・説明の編集もここで、絵（抽出時にモデルから描かれ、
好きな視点に差し替え可能）も同様です。複数のワークスペースをまとめて選び、一度にパック化・導入できます。

**Manager** — 導入済みの一覧をタイルで表示（`Ctrl` + ホイールでサイズ変更）。各タイルにパック自身の
絵、作者、署名が出ます。アンインストールせずに無効化もできます。台帳だけでなくゲーム本体も読むので、
他の何かが変更したバンドルは、その上から導入する前に見えます。

## CLI

```
dotnet run --project src/PGAssetTool.Cli -c Release -- <コマンド>
```

直接呼びたい場合、ビルドされた実行ファイルは
`src/PGAssetTool.Cli/bin/Release/net10.0-windows/win-x64/pgassettool.exe` にあります。

| コマンド | 内容 |
| --- | --- |
| `info` | 検出したインストール先とバージョンを表示。 |
| `weapons [<絞り込み>]` | 武器を一覧。名前・スラッグ・タグ・プレハブ名で絞り込み。 |
| `show <武器>` | 武器1件と、それが参照している全てを表示。ゲーム内番号（`819`）、プレハブ名（`Weapon1257`）、スラッグのいずれでも。**ゲーム内番号とプレハブ番号は別系列**です。 |
| `extract <武器>` | 武器に属するすべてを書き出し。`--workspace` を付けると、差し替え可能なファイルの対象を書いた `pgmod.json` も出力。 |
| `pack [<ディレクトリ>]` | ワークスペースから `.pgmod` を構築。抽出後に編集されたファイルだけが入ります。 |
| `convert <パス>` | 他のアセットエディタが書き出した生の `.dat` を、パック可能なワークスペースに変換。 |
| `apply <パック>` | `.pgmod` をゲームへ導入。 |
| `mods` | 導入済みの MOD を一覧。 |
| `enable <id>` / `disable <id>` | 再有効化 / アンインストールせずに無効化。 |
| `remove <id>` | アンインストール。 |
| `verify` | 全バンドルを、ゲームが記録しているハッシュと照合。 |
| `consolidate` | ダウンロードキャッシュを空にした場合の影響を報告。`--apply` は何も変わらないコピーだけを削除。 |

| オプション | 内容 |
| --- | --- |
| `--game <ディレクトリ>` | 検出したものではなくこのインストール先を使う。想定の構成を持つ任意の場所でよいので、実環境ではなくコピーを対象にできます。 |
| `--language <バンドル>` | 名前を読むローカライズバンドル（既定 `l_en-gb`）。 |
| `--out <ディレクトリ>` | 出力先。既定は `extract` が `./workspace`、`convert` が入力の隣の `converted` フォルダ。 |
| `--author <名前>` | マニフェストに記録されます。 |
| `--skin <id または名前>` | 武器のスキンも書き出す。既定は off — 1つの武器が最大十数個持つため、全部書くと作業対象1つのためにワークスペースが膨れ上がります。何を持っているかは `show` が出します。 |
| `--opaque` | テクスチャをアルファチャンネル無しで書き出す。多くは透過ではなく発光をそこに入れているため、エディタで開くとほぼ見えません。アルファ無しで戻したものは元のアルファを引き継ぎます。 |
| `--protect` | パックに署名し、zip として開けないようにする。 |
| `--force` | 既に変更済みのバンドルを `apply` にバックアップさせる。 |

```
dotnet run --project src/PGAssetTool.Cli -c Release -- weapons crystal
dotnet run --project src/PGAssetTool.Cli -c Release -- extract 819 --workspace --out workspace
dotnet run --project src/PGAssetTool.Cli -c Release -- pack workspace/0819_something
dotnet run --project src/PGAssetTool.Cli -c Release -- apply workspace/0819_something/something.pgmod
```

## ワークスペースとパック

`extract --workspace` はファイル群と `pgmod.json` を書き出します。マニフェストには差し替え可能な
各ファイルの対象と、書き出した時点のハッシュが入ります。気になるファイルだけ編集すれば、パック化は
変わったものだけを拾うので、60ファイルのワークスペースから2ファイルのパックができます。

`.pgmod` は、そのマニフェストと参照するファイル、それにパックの絵を収めた zip です。保護を有効に
すると小さなコンテナになります — 誰が作ったかを書いた読めるヘッダと、同じ zip にキーストリームを
被せたペイロード。ヘッダを読めるままにしてあるのは、Manager が中を展開せずに出所を言えるように
するためです。スクランブルは `.zip` にリネームして開くのを止めるだけで、それ以上は止めませんし、
そのつもりもありません。署名は「中身がその鍵の持ち主が入れたものである」ことを示すので、後から
書き換えられたパックは書き換えられたものとして表示されます。

### 操作の種類

| 操作 | 入力 | 対象 |
| --- | --- | --- |
| `replaceTexture` | `.png` | `Texture2D` |
| `replaceMesh` | `.glb` | `Mesh` |
| `replaceAudio` | `.wav` / `.mp3` / `.ogg` | `AudioClip` |
| `replaceRaw` | `.dat` | 任意のクラス |
| `addAsset` | `.dat` | バンドルが既に型情報を持つクラス |

上3つは誰でも普通のツールで編集できるファイルを取ります。**あるクラスが「差し替え可能」と呼ばれる
のはこれを持っているとき**です。`replaceRaw` はその一段下で、クラスを理解しないままアセット自身の
シリアライズされたバイトを書き戻します。`Material` や `Font` や `Transform` や `Shader` を変更
できるのはこれのおかげです。`addAsset` は、誰も使っていない path id に対する同じ書き込みです。

マニフェストが `formatVersion` 2 を名乗るのは下2つを使うときだけなので、それ以外の操作だけの
パックは、この機能より前のビルドでも読めるままです。

### アセットの新規追加

まだゲームに無いアセットには、誰も当てにできる path id がありません。作られたときの id は記録して
最初に試します（作者が検証したものとパックを一致させられるので）が、その番号がプレイヤーのバンドルで
予約されているわけではなく、ゲーム更新で本物のアセットが入ることもあります。そこで**身元はパックが
決めるハンドル（`newId`）**とし、新規アセットを指すものは「何を持っているか」ではなく
**ポインタがどこにあるか**を記録します。

```json
{ "op": "addAsset",
  "target": { "container": "ecw_34", "class": "Shader", "name": "font_color_fix",
              "pathId": -2415237287598442480 },
  "source": "font_color_fix.dat",
  "newId": "font_color_fix" },

{ "op": "replaceRaw",
  "target": { "container": "ecw_34", "class": "Material", "name": "debugger_20_26_map_font" },
  "source": "debugger_20_26_map_font.dat",
  "pointers": [ { "path": "m_Shader", "newId": "font_color_fix" } ] }
```

適用時に id を払い出し、それを名指すポインタをすべて埋めます。約束できないものを必要とするパックは、
辻褄を合わせにいかず理由を言って断ります — そのバンドルにそのクラスの型情報が無い、ペイロードが
ストリームに残っている、バンドルが列挙していないファイルを参照している、同クラスの別アセットが
既にその名前を使っている。

## 他のツールで作った MOD の取り込み

`convert` は、アセットエディタが書き出す `<アセット>-CAB-<ハッシュ>-<pathId>.dat` という名前の
ファイルを受け取り、ワークスペースに変換します。`.dat` は型情報を持たないので、クラスは元のアセット
から復元します。その path id にゲームがアセットを持っていない場合、その MOD は**追加している**
ということなので、クラスはバイトの方から割り出します — バンドルが記述する各型でパースしてみて、
書き戻してバイト単位で一致したものを採用します。

張り替えが必要なポインタは、宣言ではなく**検出**します。作者のファイルは既に、そのエディタが振った
id で新規アセットを指しているので、その番号を持つポインタこそが書き換えるべきものです。

```
pgassettool convert path/to/mod --out PGAssetTool-data/workspace/my_mod
pgassettool pack PGAssetTool-data/workspace/my_mod
pgassettool apply PGAssetTool-data/workspace/my_mod/my_mod.pgmod
```

ワークスペースルートへ変換しておくと、結果は GUI の Editor にも並ぶので、以降のパック化・導入・
管理はそちらから行えます。

## データの置き場所

このツールが書き出すものはすべて、実行ファイルの隣の `PGAssetTool-data/` に入ります。レジストリも
`%APPDATA%` も使いません。リポジトリ内で動かした場合はリポジトリのルートに解決されるので、どの
ビルドも同じ場所を共有します。

```
PGAssetTool-data/
  settings.json          設定
  author.key             パックの署名に使う鍵
  mods/                  ワークスペース無しで再導入できるよう保管されたパック
  workspace/             抽出・変換したワークスペース
  installs/<ゲーム>/
    backup/              最初に書き込む前の各バンドル
```

## 安全のための決まり

- **ゲームの起動中は一切書き込みません。** Manager も Editor の「パックして適用」も、閉じるまで拒否します。
- バンドルは最初に書き込む前にバックアップされます。導入・切り替え・削除はいずれも「影響するバンドルを
  全部戻してから、有効なものを導入順に適用し直す」形で動きます。これにより、バンドルを共有する別の
  MOD が巻き添えで消えることも、変更が積み重なることもありません。
- 他の何かが既に変更していてバックアップの無いバンドルに対して、`apply` は拒否します。`--force` を
  付けたときだけ、その中身を「元の状態」として受け入れます。
- `verify` は全バンドルをゲームの記録するハッシュと照合し、その差分のどれが導入済み MOD で説明が
  付くかを示します。

## 変更の検証

```
dotnet test -c Release
dotnet run --project src/PGAssetTool.Gui -c Release -- --self-test
```

`dotnet test` はゲーム不要で、CI が回しているのもこちらです。**本当の検証は `--self-test`** の方で、
実インストールに対してツール全体を動かします — 武器の解決、プレビューのデコード、実際のウィンドウを
構築して何が入ったかを読み返し、そして抽出・編集・パック化・導入・切り替え・削除を本当に実行します。
ゲームが起動していれば開始しません。削除するのは自分のパックだけ、専用のワークスペースと設定を使い、
最後に作者の設定ファイルがバイト単位で元のままであることを検証します。

## まだできないこと

- **`.assets` への書き込み**（`*_Data` 配下のファイル）とスプライトアトラス。現状 書き込むのは
  AssetBundle だけです。
- **フォントとシェーダーの編集可能な形式。** バイトの書き戻しは `replaceRaw` で通りますが、
  「編集するための形式」がありません。あるクラスが差し替え可能と言えるにはそれが要ります。
- **JSON フィールドダンプの編集。** 読むために書いているだけで、読み戻す口がありません。
  `Material` の1フィールドを変えるにも、今は生バイトを経由する必要があります。
- **スキン自身のモデルのプレビュー。** 抽出は対応済みですが、プレビューの選択肢はテクスチャだけです。
